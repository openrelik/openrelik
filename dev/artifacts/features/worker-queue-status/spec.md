# Spec: Worker and queue status page

Implements `idea.md` (#152) and `design.md`. Incorporates validated backend and UI architecture from the `prototype/worker-queue-status` worktree.

## Scope

- Add `GET /api/v1/taskqueue/status`: parallel Celery `inspect()` using isolated short-lived `Celery` instances per thread (with explicit Redis socket timeouts and `broker_pool_limit=None`), Redis pipeline (`LLEN` + bounded `LRANGE` header scan across priority keys, `SCAN_LIMIT = 2000`), offline queue backlog discovery via `scan_iter(match="openrelik-*")`, internal-worker classification (`openrelik-hashing`), zero raw task arguments/paths, and an in-memory + Redis `5s` TTL cache with a bounded single-flight lock (`1s` cooldown on `?refresh=true`).
- Add `GET /api/v1/workflows/active`: non-deleted workflows with non-terminal tasks, DAG-aware liveness and pending split (`tasks_queued` vs. `tasks_waiting`, ignoring `PENDING` tasks downstream of failures), Celery/Redis live-UUID cross-check (`stall_reason`: `no_worker` / `stalled` with a 60s grace window and truncation guard), and folder ACL enforcement via `check_user_access` (`Role.VIEWER`/`EDITOR`/`OWNER`, preserving `Role.NO_ACCESS` denies).
- Add `GET /api/v1/configs/status`: single grouped scan over `file` (active counts/bytes, unpurged soft-deleted trash counts/bytes, per-provider totals), `folder` (total + root), `workflow` total, and `shutil.disk_usage()` per configured storage provider (omitting raw host paths), cached in Redis for `60s` (`5s` cooldown on `?refresh=true`).
- Add a partial database index on `task (workflow_id)` for non-terminal task states so active-workflow lookups stay bounded as historical tasks grow, and add an explicit HTTP `timeout=10` to Prometheus range queries in `server/src/api/v1/metrics.py`.
- Replace Runestone's `MetricsView.vue` with `StatusView.vue` at `/status` (redirecting `/metrics` to `/status`), updating `StatusBar.vue`, implementing the prototype's calm zero-badge console layout (`StatusSummaryStrip`, `QueueStatusTable`, `ActiveWorkflowsTable`, `WorkerStatusTable`, `SystemStorageSection`, and collapsible `Historical metrics`), `rem`-only typography, non-overlapping auto-refresh, and sign-out state cleanup.
- Out of scope: changes to `web/sunstone`, `loadavg` plotting or changes to `server/src/metrics/exporter.py` (including its `CounterMetricFamily` queue-length bug), modifying `server/src/mediator/mediator.py` to rewrite downstream task states on failure, workflow cancel/revoke mutations, or authz changes to legacy `/taskqueue/tasks/*` endpoints.

## Requirements

- R1: `GET /api/v1/taskqueue/status` (authenticated via `get_current_active_user` and `verify_csrf`) runs Celery `inspect(timeout=1.0)` calls (`stats`, `active`, `reserved`, `active_queues`, `registered("metadata")`) concurrently using isolated short-lived `Celery` instances (`broker_pool_limit=None`, explicit `socket_timeout` and `socket_connect_timeout`, closed in `finally`), discovers offline OpenRelik queues in Redis via `scan_iter(match="openrelik-*")`, and uses a timeout-bounded Redis client pipeline (`LLEN` + bounded `LRANGE 0 1999`) across each queue and its Kombu priority sub-keys (`\x06\x163`, `\x06\x166`, `\x06\x169`) to count queued messages by `headers["task"]` and collect queued task UUIDs (`headers["id"]`).
- R2: `GET /api/v1/taskqueue/status` returns `TaskqueueStatusResponse` with:
  - `collected_at` (UTC ISO-8601 timestamp);
  - `summary`: `workers_online`, `workers_busy`, `workers_idle`, `slots_busy`, `slots_total`, `tasks_running`, `tasks_reserved`, `tasks_queued`, `tasks_waiting` (`tasks_reserved + tasks_queued`);
  - `queues`: sorted list of online queues plus any offline queue with `queued > 0`, each with `name`, `is_internal`, `workers_online`, `slots_busy`, `slots_total`, `running`, `reserved`, `queued` (exact `LLEN`), `waiting` (`reserved + queued`), `scan_truncated` (`queued > 2000`), `scan_limit`, and `tasks` (per `task_name` with `display_name`, `running`, `reserved`, `queued`, `waiting`);
  - `workers`: sorted list of online worker nodes with `hostname`, `status` (`"online"`), `queues`, `is_internal`, `slots_busy`, `slots_total`, `reserved`, `processed`, `uptime`, `prefetch_count`, and `registered_tasks`.
- R3: Internal workers whose tasks register without a `metadata` dict (such as `openrelik-hashing`) appear in `queues` and `workers` with `is_internal: true` without affecting `get_registered_tasks()`. Offline queues without online worker metadata are not misclassified as `is_internal: true`.
- R4: `GET /api/v1/taskqueue/status` never exposes raw Celery task `args`, `kwargs`, `input_files`, `output_path`, `workflow_id`, or `task_config` fields.
- R5: `GET /api/v1/taskqueue/status` uses an in-memory fast path + Redis cache (`openrelik:taskqueue:status:v1`, TTL `5s`) guarded by a timeout-bounded lock (`_status_lock.acquire(timeout=...)`) so concurrent callers never block indefinitely or exhaust DB connections; `?refresh=true` bypasses cache when past a `1s` cooldown. Returns HTTP `200` with zeroed counts when no workers are online, and HTTP `503` when Redis is unreachable.
- R6: `GET /api/v1/workflows/active` (authenticated) returns `list[ActiveWorkflowResponse]` for non-deleted workflows (in non-deleted folders) that are active under DAG-aware `summarize_workflow_tasks(spec_json, tasks, ...)` (ignoring `PENDING` tasks downstream of failures, splitting `tasks_queued` whose upstreams succeeded from `tasks_waiting` blocked on upstream steps), cross-checked against cached Celery/Redis live task UUIDs and online queues to set `stall_reason` (`"no_worker"`, `"stalled"` past a 60s grace period unless the queue scan was truncated, or `None`), filtered by `check_user_access(db, current_user, VIEW_ROLES, folder=workflow.folder)` (preserving `Role.NO_ACCESS` denies), ordered newest updated first.
- R7: `GET /api/v1/configs/status` (authenticated) returns `SystemStorageStatusResponse` containing active `files_count`, `files_total_bytes`, `deleted_unpurged_files_count`, `deleted_unpurged_bytes`, `folders_count`, `root_folders_count`, `workflows_count`, and per-provider `storage_providers` (`name`, `display_name`, `mode`, `is_default`, `available`, `total_bytes`, `used_bytes`, `free_bytes`, `used_percent`, `file_count`, `file_bytes` — never exposing raw host filesystem paths), cached in Redis (`openrelik:system:storage_status:v1`, TTL `60s`, `5s` refresh cooldown).
- R8: An Alembic migration adds a partial index `ix_task_workflow_id_non_terminal` on `task (workflow_id)` filtered to `status_short IS NULL OR status_short NOT IN ('SUCCESS', 'FAILURE', 'REVOKED', 'REJECTED')` (`postgresql_where` and `sqlite_where`), and `query_prometheus_range()` in `server/src/api/v1/metrics.py` passes an explicit `timeout=10`.
- R9: Runestone replaces `/metrics` (`MetricsView.vue`) with `/status` (`StatusView.vue`, route name `status`), adds a redirect from `/metrics` to `/status`, and updates `StatusBar.vue`'s footer link from `metrics` (`/metrics`) to `status` (`/status`). (The UI switcher `uiSwitch.ts` was removed in #146.)
- R10: `StatusView.vue` loads cluster status (`GET /taskqueue/status`), active workflows (`GET /workflows/active`), and storage status (`GET /configs/status`) in parallel through `useStatus` backed by `useQueryCache` (`5s` stale for live status/workflows, `60s` stale for storage so 15s auto-refresh does not re-scan Postgres), degrades independently when any feed or Prometheus fails, and clears all cached status data via `clearStatus()` in `web/runestone/src/stores/auth.ts` on sign-out / 401.
- R11: `StatusView.vue` implements the console layout validated in `prototype/worker-queue-status`:
  - top bar with `<BrandLink />`, `<h1>System status</h1>` (no `PathBar` prompt), UTC snapshot timestamp, `appearance-none` Auto-refresh select (`No auto-refresh`, `15s`, `1m`, `5m`, persisted with `document.hidden`, `navigator.onLine`, and in-flight non-overlap guards), and manual `Refresh`;
  - aggregate summary strip (`Online workers`, `Capacity in use` with `N free` and red-full / amber-1-left thresholds, `Running tasks`, `Queued tasks`, `Active workflows`);
  - `Storage` section directly below the summary strip (`Files`, `Total size`, uncolored `Trash` count + bytes, `Folders` + root, `Workflows`, and per-provider disk usage table with bar colored amber `>=80%` and red `>=90%`, omitting redundant `server_default` text and hiding `default` when only one provider exists);
  - `Queues and registered tasks` table collapsed by default (`Queue / Task | Workers | Running | Queued`, merging capacity into `Running` with red-full / amber-1-left thresholds, combining prefetched + broker in `Queued` with hover breakdown, showing offline queues in red);
  - `Active workflows` table with clickable links to `/folder/:folderId` and inline `·`-separated progress (`done/total`, amber `running`, `queued` with offline-queue tooltip when `no_worker`, muted `waiting`, red `failed`, red `stalled`);
  - `Workers` table (`Worker | State | Queues | Running | Prefetched | Processed | Uptime`) with plain muted `idle` and amber `busy`;
  - collapsible `Historical metrics` section (collapsed by default) preserving the existing 10 Prometheus `MetricCard` charts and `period`/`every` controls, skipped during auto-refresh when collapsed.
- R12: Runestone changes add zero new runtime dependencies, use `rem` font sizes everywhere (respecting `compact`/`normal`/`large` presets), use zero `.badge` boxes and zero pulsating dots on the Status page, import icons only via `@/components/icons`, use `.tabular` on dynamic numbers and `font-mono` on identifiers, use zero `v-html`, and achieve at least 85% V8 line coverage on every touched runtime file.
