# Spec: Serve multiple web UIs with user switching

Implements idea.md (#107).

## Scope

- Keep publishing `openrelik-ui` from `web/sunstone/Dockerfile` unchanged for existing single-container deployments, and publish `openrelik-web-sunstone` (`web/sunstone/Dockerfile`), `openrelik-web-runestone` (`web/runestone/Dockerfile`), and `openrelik-web-router` (`web/router/Dockerfile`) alongside it.
- Build `openrelik-web-router` in `web/router/` on port `8711` as a config-driven Nginx router with zero hardcoded UI containers: it reads registered UIs from `OPENRELIK_UIS` (`id|Label|upstream_url,...`) and `OPENRELIK_DEFAULT_UI`, reads its DNS resolver from `/etc/resolv.conf` for Docker Compose and Kubernetes compatibility, routes browser requests by the `openrelik_ui` cookie and `/assets/<id>/` prefixes, exposes `GET /__openrelik/uis.json` for dynamic UI discovery, and serves a static fallback chooser at `/__openrelik/ui` (`/__openrelik/switch/<id>`) so third-party UI containers without native switcher controls can still switch back.
- Namespace static assets under `assets/sunstone` and `assets/runestone` (including Runestone's self-hosted IBM Plex fonts under `public/assets/runestone/fonts`), update `substitute_env_variables.sh` in both UIs to match, and set `Cache-Control: no-cache` and `Vary: Cookie` on `/index.html` while keeping standalone `openrelik-ui` working.
- Add dynamic UI switching controls in settings, menu, and `/login` in both `web/sunstone` and `web/runestone` driven by `GET /__openrelik/uis.json`, automatically hiding the controls on standalone `openrelik-ui` or single-UI setups (`uis.length <= 1`), normalizing routes to canonical OpenRelik paths when switching, and clearing cached Runestone session metadata on Sunstone logout.
- Switch `deploy/docker/docker-compose.yml` and `deploy/docker/config.env` to `openrelik-web-router` on `:8711` fronting internal `openrelik-web-sunstone` and `openrelik-web-runestone` containers via `OPENRELIK_UIS` and `OPENRELIK_DEFAULT_UI=sunstone`.
- Update `compose.yml`, `.env.example`, and `dev/tools/devctl/` so `./devctl stack up` serves registered UIs through `web-router` on `UI_PORT` (`3000` + worktree slot) with Vite HMR WebSocket forwarding, removing the separate `RUNESTONE_PORT` host port.
- Update `.github/images.toml`, `.github/scripts/images.py`, `dev/tools/devctl/src/devctl/release.py`, and `web/README.md` so `ui-v*` releases version and build all four UI images (`openrelik-ui`, `openrelik-web-sunstone`, `openrelik-web-runestone`, and `openrelik-web-router`), superseding the image-swap cutover in `dev/artifacts/features/runestone-web-ui/spec.md` R13/T16.
- Out of scope: backend API or database changes, Helm chart updates in the external `google/osdfir-infrastructure` repository (tracked separately), and changing `OPENRELIK_DEFAULT_UI` from `sunstone` to `runestone`.

## Requirements

- R1: `web/router/Dockerfile`, `web/router/nginx/nginx.conf.template` (or `nginx.conf`), and `web/router/nginx/configure_router.sh` build an `nginx:stable-alpine` image (`openrelik-web-router`) on port `8711` with no hardcoded UI names in routing logic: `configure_router.sh` extracts the nameserver from `/etc/resolv.conf` (wrapping IPv6 literals in brackets and falling back to `127.0.0.11`), parses `OPENRELIK_UIS` (`id|Label|upstream_url` comma-separated entries, defaulting to `sunstone|Sunstone|http://openrelik-web-sunstone:8711,runestone|Runestone|http://openrelik-web-runestone:8711`), validates each `id` (`^[a-z0-9][a-z0-9-]*$`) and `http(s)://` upstream URL, resolves `OPENRELIK_DEFAULT_UI` (falling back to the first configured UI when unset or not in `OPENRELIK_UIS`), generates `/assets/<id>/` proxy rules for every configured UI, routes all other paths (including HTTP/1.1 WebSocket upgrades) by allowlisted `$cookie_openrelik_ui` with `Vary: Cookie`, serves `GET /__openrelik/uis.json` (`Cache-Control: no-store`, `Content-Type: application/json`) returning `{ "default": "<id>", "uis": [{ "id": "<id>", "name": "<label>" }] }` without exposing internal upstream URLs, and serves a zero-JS HTML chooser at `GET /__openrelik/ui` linking to allowlisted `GET /__openrelik/switch/<id>` endpoints that set the `openrelik_ui=<id>` cookie (`Path=/; Max-Age=31536000; SameSite=Lax`, plus `; Secure` on `https`) and redirect (`302`) to `/`.
- R2: `web/sunstone` builds static bundles under `assets/sunstone` (`vite.config.mjs`), substitutes `PLACEHOLDER_VITE_OPENRELIK_*` in `/usr/share/nginx/html/assets/sunstone` (`web/sunstone/nginx/substitute_env_variables.sh`), and serves `/index.html` with `Cache-Control: no-cache` and `Vary: Cookie` (`web/sunstone/nginx/nginx.conf`) while continuing to work standalone as `openrelik-ui`; `web/runestone` builds bundles under `assets/runestone` (`vite.config.ts`), serves self-hosted IBM Plex fonts from `public/assets/runestone/fonts` (`web/runestone/src/assets/main.css`), substitutes `PLACEHOLDER_VITE_OPENRELIK_*` in `/usr/share/nginx/html/assets/runestone` (`web/runestone/nginx/substitute_env_variables.sh`), and serves `/index.html` with `Cache-Control: no-cache` and `Vary: Cookie` (`web/runestone/nginx/nginx.conf`); and both Vite configs honour `VITE_HMR_CLIENT_PORT` for `server.hmr.clientPort` when set.
- R3: `web/sunstone` provides `web/sunstone/src/utils/uiSwitch.js` that fetches and memoizes `GET /__openrelik/uis.json`, verifies a JSON response with `uis`, and exposes all entries with `id !== "sunstone"`; `UserSettings.vue`, `SystemMenu.vue`, and `Login.vue` dynamically render switch actions for every alternative UI returned (and hide switcher UI completely when standalone or when fewer than two UIs are configured); switching sets `openrelik_ui=<targetId>; Path=/; Max-Age=31536000; SameSite=Lax` (plus `; Secure` on `https:`), normalizes `/my-folders` and `/shared-with-me` to `/`, `/folder/:folderId/file/:fileId/details` and `/folder/:folderId/file/:fileId/content` to `/folder/:folderId/file/:fileId`, and `/folder/:folderId/investigation` to `/folder/:folderId` while preserving `/`, `/metrics`, `/folder/:folderId`, `/folder/:folderId/file/:fileId`, and `/login?redirect=...`, and `ProfileMenu.vue` clears `openrelik.auth.user` from `sessionStorage` on logout.
- R4: `web/runestone` provides `web/runestone/src/utils/uiSwitch.ts` that fetches and memoizes `GET /__openrelik/uis.json` and exposes all entries with `id !== "runestone"`; `SettingsDialog.vue`, `AccountDialog.vue`, and `LoginView.vue` (using only existing runtime dependencies and `@/components/icons`) dynamically render switch actions for every alternative UI returned and hide switcher UI when standalone or when fewer than two UIs are configured; switching sets `openrelik_ui=<targetId>; Path=/; Max-Age=31536000; SameSite=Lax` (plus `; Secure` on `https:`), preserves `/`, `/login` (with safe relative `?redirect=`), `/metrics`, `/folder/:id`, and `/folder/:folderId/file/:fileId`, falls back to `/` for `/case/...` or unrecognised paths, and maintains at least 85% V8 line coverage on every touched runtime file.
- R5: `deploy/docker/docker-compose.yml` and `deploy/docker/config.env` replace the single `openrelik-ui` service with `openrelik-web-router` bound to `127.0.0.1:8711:8711` configured via `OPENRELIK_DEFAULT_UI=${OPENRELIK_DEFAULT_UI:-sunstone}` and `OPENRELIK_UIS` fronting internal `openrelik-web-sunstone` and `openrelik-web-runestone` services without extra host ports, passing `OPENRELIK_SERVER_URL`, `OPENRELIK_API_VERSION`, and `OPENRELIK_AUTH_METHODS` to both UI containers.
- R6: `compose.yml`, `.env.example`, and `dev/tools/devctl/src/devctl/{checkout,envfile,stacks}.py` serve `web-router` (`./web/router`) on `127.0.0.1:${UI_PORT:-3000}:8711` configured with `OPENRELIK_DEFAULT_UI=${OPENRELIK_DEFAULT_UI:-sunstone}` and `OPENRELIK_UIS` pointing to internal `web-sunstone:3000` and `web-runestone:3050` Vite servers (`VITE_HMR_CLIENT_PORT=${UI_PORT:-3000}`), removing the separate `RUNESTONE_PORT` host port allocation.
- R7: `.github/images.toml` keeps `openrelik-ui` (`web/sunstone/Dockerfile`) unchanged and registers `openrelik-web-sunstone` (`web/sunstone/Dockerfile`), `openrelik-web-runestone` (`web/runestone/Dockerfile`), and `openrelik-web-router` (`web/router/Dockerfile`); `.github/scripts/images.py` passes `check`, selects all four `platform` images under `web/` on `ui-v*` tags while keeping per-directory `--changed` selection on PR merges, and verifies all `web/*/package.json` versions match `ui-v*`; `dev/tools/devctl/src/devctl/release.py` updates all `web/*/package.json` manifests in `release_ui`; and `web/README.md` documents the four UI images, `OPENRELIK_UIS`, `OPENRELIK_DEFAULT_UI`, `/__openrelik/uis.json`, `/__openrelik/ui`, and how to register custom third-party frontend containers.

## Rollout

- No database migrations or server configuration changes. API, authentication callbacks, file uploads, and file downloads continue talking directly to `openrelik-server` on `:8710`.
- Existing deployments that pull `ghcr.io/openrelik/openrelik-ui` without updating their Compose or Kubernetes manifests continue receiving standalone `sunstone` on port `8711` with UI switcher controls hidden.
- Fresh installs via `deploy/docker/install.sh` and deployments updating `deploy/docker/docker-compose.yml` and `deploy/docker/config.env` run `openrelik-web-router` on `:8711` (`OPENRELIK_DEFAULT_UI=sunstone`) in front of internal `openrelik-web-sunstone` and `openrelik-web-runestone` containers, and operators can register custom frontend containers by adding them to `OPENRELIK_UIS`.
- Local checkouts running `./devctl stack up` switch from two host UI ports (`UI_PORT` and `RUNESTONE_PORT`) to the single `UI_PORT` router (`web-router`) automatically when the stack is recreated.
- Kubernetes deployments using `google/osdfir-infrastructure` continue working on `openrelik-ui` until a companion Helm chart update in `charts/openrelik` switches the frontend Deployment to `openrelik-web-router` and populates `OPENRELIK_UIS` from Helm values.
