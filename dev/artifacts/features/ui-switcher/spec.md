# Spec: Serve multiple web UIs with user switching

Implements idea.md (#107).

## Scope

- Add a lightweight Nginx router image in `web/router/` (`openrelik-ui`) that listens on port `8711`, reads its DNS resolver from `/etc/resolv.conf` so it works on both Docker Compose and Kubernetes, defaults to `OPENRELIK_DEFAULT_UI=sunstone`, and routes browser requests between separate `sunstone` and `runestone` containers using the `openrelik_ui` cookie.
- Namespace static Vite bundle paths under `assets/sunstone` and `assets/runestone`, update `substitute_env_variables.sh` in both UIs to match, and set `Cache-Control: no-cache` and `Vary: Cookie` on `/index.html` so switching UIs in one tab never serves stale HTML or breaks lazy chunk loads in another open tab.
- Add UI switching controls in settings, menu, and `/login` in both `web/sunstone` and `web/runestone`, mapping routes between the two UIs and clearing cached Runestone session metadata on Sunstone logout.
- Update `deploy/docker/docker-compose.yml` and `deploy/docker/config.env` to run `openrelik-web-sunstone` and `openrelik-web-runestone` behind `openrelik-ui` on `:8711`.
- Update `compose.yml`, `.env.example`, and `dev/tools/devctl/` so `./devctl stack up` serves both UIs through the `web` router on `UI_PORT` (`3000` + worktree slot) with Vite HMR WebSocket forwarding, removing the separate `RUNESTONE_PORT` host port.
- Register `openrelik-ui` (`web/router`), `openrelik-web-sunstone` (`web/sunstone`), and `openrelik-web-runestone` (`web/runestone`) in `.github/images.toml`, update `.github/scripts/images.py` and `dev/tools/devctl/src/devctl/release.py` so `ui-v*` releases version and build all UI images under `web/`, and document the router in `web/README.md` (superseding the image-swap cutover in `dev/artifacts/features/runestone-web-ui/spec.md` R13/T16).
- Out of scope: backend API or database changes, Helm chart updates in the external `google/osdfir-infrastructure` repository (tracked separately), and changing `OPENRELIK_DEFAULT_UI` from `sunstone` to `runestone`.

## Requirements

- R1: `web/router/Dockerfile`, `web/router/nginx/nginx.conf`, and `web/router/nginx/configure_router.sh` build an `nginx:stable-alpine` image on port `8711` that extracts the nameserver from `/etc/resolv.conf` (wrapping IPv6 literals in brackets and falling back to `127.0.0.11`), validates `OPENRELIK_DEFAULT_UI` (`sunstone` or `runestone`, defaulting to `sunstone`), defaults `OPENRELIK_SUNSTONE_UPSTREAM` to `http://openrelik-web-sunstone:8711` and `OPENRELIK_RUNESTONE_UPSTREAM` to `http://openrelik-web-runestone:8711`, routes `/assets/sunstone/` to the Sunstone upstream, routes `/assets/runestone/` and `/fonts/` to the Runestone upstream, and routes all other paths (including HTTP/1.1 WebSocket upgrades) by allowlisted `$cookie_openrelik_ui` (`sunstone` or `runestone`, otherwise `OPENRELIK_DEFAULT_UI`) with `Vary: Cookie`.
- R2: `web/sunstone` builds static bundles under `assets/sunstone` (`vite.config.mjs`), substitutes `PLACEHOLDER_VITE_OPENRELIK_*` in `/usr/share/nginx/html/assets/sunstone` (`web/sunstone/nginx/substitute_env_variables.sh`), and serves `/index.html` with `Cache-Control: no-cache` and `Vary: Cookie` (`web/sunstone/nginx/nginx.conf`); `web/runestone` does the same under `assets/runestone` (`vite.config.ts`, `web/runestone/nginx/substitute_env_variables.sh`, `web/runestone/nginx/nginx.conf`); and both Vite configs honour `VITE_HMR_CLIENT_PORT` for `server.hmr.clientPort` when set.
- R3: `web/sunstone` provides `web/sunstone/src/utils/uiSwitch.js` and exposes actions to switch to Runestone in `UserSettings.vue`, `SystemMenu.vue`, and `Login.vue` that set `openrelik_ui=runestone; Path=/; Max-Age=31536000; SameSite=Lax` (plus `; Secure` on `https:`), map `/my-folders` and `/shared-with-me` to `/`, `/folder/:folderId/file/:fileId/details` and `/folder/:folderId/file/:fileId/content` to `/folder/:folderId/file/:fileId`, and `/folder/:folderId/investigation` to `/folder/:folderId` while preserving `/`, `/metrics`, `/folder/:folderId`, `/folder/:folderId/file/:fileId`, and `/login?redirect=...`, and `ProfileMenu.vue` clears `openrelik.auth.user` from `sessionStorage` on logout.
- R4: `web/runestone` provides `web/runestone/src/utils/uiSwitch.ts` and exposes actions to switch to Sunstone in `SettingsDialog.vue`, `AccountDialog.vue`, and `LoginView.vue` (using only existing runtime dependencies and `@/components/icons`) that set `openrelik_ui=sunstone; Path=/; Max-Age=31536000; SameSite=Lax` (plus `; Secure` on `https:`), preserve `/`, `/login` (with safe relative `?redirect=`), `/metrics`, `/folder/:id`, and `/folder/:folderId/file/:fileId`, fall back to `/` for `/case/...` or unrecognised paths, and maintain at least 85% V8 line coverage on every touched runtime file.
- R5: `deploy/docker/docker-compose.yml` and `deploy/docker/config.env` keep `openrelik-ui` bound to `127.0.0.1:8711:8711` with `OPENRELIK_DEFAULT_UI=${OPENRELIK_DEFAULT_UI:-sunstone}` and run `openrelik-web-sunstone` and `openrelik-web-runestone` on the internal Compose network without extra host ports, passing `OPENRELIK_SERVER_URL`, `OPENRELIK_API_VERSION`, and `OPENRELIK_AUTH_METHODS` to both UI containers.
- R6: `compose.yml`, `.env.example`, and `dev/tools/devctl/src/devctl/{checkout,envfile,stacks}.py` serve the `web` router (`./web/router`) on `127.0.0.1:${UI_PORT:-3000}:8711` forwarding to internal `web-sunstone:3000` and `web-runestone:3050` Vite servers with `VITE_HMR_CLIENT_PORT=${UI_PORT:-3000}` and `OPENRELIK_DEFAULT_UI=${OPENRELIK_DEFAULT_UI:-sunstone}`, removing the separate `RUNESTONE_PORT` host port allocation.
- R7: `.github/images.toml` lists `openrelik-ui` (`web/router/Dockerfile`), `openrelik-web-sunstone` (`web/sunstone/Dockerfile`), and `openrelik-web-runestone` (`web/runestone/Dockerfile`); `.github/scripts/images.py` passes `check`, selects all `platform` images under `web/` on `ui-v*` tags while keeping per-directory `--changed` selection on PR merges, and verifies all `web/*/package.json` versions match `ui-v*`; `dev/tools/devctl/src/devctl/release.py` updates all `web/*/package.json` manifests in `release_ui`; and `web/README.md` documents the router, UI images, `openrelik_ui` cookie, and `OPENRELIK_DEFAULT_UI`.

## Rollout

- No database migrations or server configuration changes. API, authentication callbacks, file uploads, and file downloads continue talking directly to `openrelik-server` on `:8710`.
- `deploy/docker/docker-compose.yml` adds internal `openrelik-web-sunstone` and `openrelik-web-runestone` services behind `openrelik-ui`, and `deploy/docker/config.env` adds `OPENRELIK_DEFAULT_UI=sunstone`. Fresh installs via `deploy/docker/install.sh` pick up both files automatically; existing Docker Compose deployments upgrading to the next minor release pull the updated `docker-compose.yml` and `config.env`.
- Local checkouts running `./devctl stack up` switch from two host UI ports (`UI_PORT` and `RUNESTONE_PORT`) to the single `UI_PORT` router automatically when the stack is recreated.
- Kubernetes deployments using `google/osdfir-infrastructure` need a companion Helm chart update in `charts/openrelik` to add the `openrelik-web-sunstone` and `openrelik-web-runestone` Deployments/Services behind the existing frontend Service and pass `OPENRELIK_DEFAULT_UI`, `OPENRELIK_SUNSTONE_UPSTREAM`, and `OPENRELIK_RUNESTONE_UPSTREAM`.
