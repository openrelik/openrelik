# Spec: Runestone web UI

Implements idea.md (#96) and design.md.

## Scope

- Import the `openrelik-new-ui` prototype into `web/runestone/` (`openrelik-web-runestone`) in one mechanical step as a Vue 3, TypeScript, and Tailwind CSS v4 web UI with six runtime packages (`vue`, `vue-router`, `pinia`, `tailwindcss`, `@tailwindcss/vite`, `lucide-vue-next`), Apache 2.0 headers, monorepo version tracking, `web/runestone/AGENTS.md`, and runtime Nginx container configuration.
- Set up Vitest with `happy-dom`, `@vue/test-utils`, and `@vitest/coverage-v8`, and add unit and component tests across TypeScript modules (`api`, `utils`, `stores`, `composables`, `directives`) and `.vue` views and components before refactoring or extending behaviour.
- Replace the hardcoded viewer switch in `FileContent.vue` with a declarative `FileViewerPlugin` registry (`src/components/viewers/registry.ts`) shipping `table`, `rendered`, `text`, and `hex` plugins, and add forensic-scale row windowing in `FolderTable.vue` plus explicit partial-stream bounds in `TableViewer.vue`.
- Update `GET /api/v1/files/{file_id}/download` in `server/src/api/v1/files.py` to expose `Content-Range` and `Accept-Ranges` to cross-origin browsers.
- Run `web-runestone` (`RUNESTONE_PORT`, `:3050` + slot) alongside `web-sunstone` (`UI_PORT`, `:3000` + slot) by default in `./devctl stack up`, add `.github/workflows/frontend-runestone-tests.yml`, and publish `ghcr.io/openrelik/openrelik-web-runestone`.
- Close the three Sunstone parity gaps: external OAuth/OIDC login providers and legacy `/my-folders` and `/shared-with-me` redirects; AI file summaries and streaming SSE file chat; and workflow-level Markdown reports plus LLM workflow naming.
- Cut `openrelik-ui` and the default dev `UI_PORT` over from `web/sunstone` to `web/runestone` in the final sequential phase after parity verification.
- Out of scope: SQLite/DuckDB SQL viewer (`SqlTables.vue`, deprecated), agent investigations (`Investigation.vue`, being replaced separately), extracting shared client code into `web/shared/`, and deleting `web/sunstone/`.

## Requirements

- R1: `web/runestone/` installs cleanly with `npm ci` on Node 22+, passes `npm run format:check`, `npm run lint:check`, `npm run type-check` (`vue-tsc --build`), `npm run test:coverage` (`vitest run --coverage` with `happy-dom` and `@vue/test-utils`), and `npm run build`, carries the Apache 2.0 `Copyright 2026 Google LLC` header on all `.ts`, `.vue`, `.css`, and `.sh` files, tracks root `VERSION` in `web/runestone/package.json` (`check-versions.py` passes), and declares only `vue`, `vue-router`, `pinia`, `tailwindcss`, `@tailwindcss/vite`, and `lucide-vue-next` under runtime `dependencies`.
- R2: `FolderView`, `FileView`, and `MetricsView` use the edge-to-edge three-tier console layout (`PathBar`, scrollable main workspace with collapsible resizable side pane, `StatusBar`), self-hosted IBM Plex Sans and IBM Plex Mono fonts with zero outbound font/asset requests, OKLCH `data-theme` light/dark tokens clearing WCAG contrast targets, keyboard table traversal and `Shift` range selection, `⌘K`/`g` path/command prompt, `?` shortcut help, and a modal stack where `Escape` closes only the topmost active edit, menu, or dialog.
- R3: `web/runestone/src/api/` uses native `fetch` (plus `XMLHttpRequest` for chunked upload progress and `fetch` `ReadableStream` for SSE), deduplicates concurrent `401` refreshes via `POST /auth/refresh`, automatically fetches `/auth/csrf` and retries `X-CSRF-Token` on unsafe methods, tracks reachability and in-flight request counts, and serves reads through `useQueryCache` (`ensure(key, fetcher)`) with background stale-while-revalidate updates while keying folders and files separately (`folder:{id}` and `file:{id}`) in `stores/items.ts`.
- R4: `/` paginates `GET /api/v1/folders/all/` with owner avatars, case badges, and next-page prefetch; `/case/:ref(.*)` resolves case references via `GET /api/v1/folders/case/{ref}`; `/folder/:id` supports sorting, empty-file folding, inline folder creation/renaming, soft delete, `CaseRefPopover`, `ShareDialog` user/group roles, and fixed-height row windowing in `FolderTable.vue` so folders with 50,000+ files mount only visible DOM rows; and `useUploadQueue` persists across route changes, uploads chunks sequentially per file, retries `503` chunks with backoff, and restarts `429` expired uploads.
- R5: `RunDialog` and `WorkflowPanel` support single-worker quick-runs and full workflow authoring (`WorkflowTree` and custom packed-column `WorkflowGraph` with parallel group split/merge, Celery chord joins, fan-out stack folding, background draft saves, 3-second polling while tasks run, `TaskInspector`, and `TaskReportDialog`), display workflow-level Markdown reports from `GET /api/v1/workflows/{id}/report/`, and support LLM workflow naming via `GET /api/v1/folders/{id}/workflows/{id}/generate_name/` when `settings.ai.workflowNames` and server `active_llms` are enabled.
- R6: `web/runestone/src/components/viewers/registry.ts` matches `FileViewerPlugin` entries against file metadata sorted by priority with `HexViewer` as fallback, selects plugins matching URL `#mark` or `?view=<id>`, preserves mounted state across tab switches on the same file when `keepAliveForSameFile` is true, teleports contextual inspectors into `#file-side-inspector` in `FileSidePanel.vue`, registers `table` (`TableViewer` with explicit byte/row prefix caps and UI prompts when sorting or filtering partial multi-gigabyte CSV/TSV/JSONL streams), `rendered` (`MarkdownViewer`), `text` (`TextViewer`), and `hex` (`HexViewer`), and aborts any `filesApi.readRange()` response whose status is not `206` or whose `Content-Range` does not match the requested slice before reading its body.
- R7: `GET /api/v1/files/{file_id}/download` in `server/src/api/v1/files.py` sets `Access-Control-Expose-Headers: Content-Disposition, Content-Range, Accept-Ranges` so cross-origin `Range` requests can read `Content-Range` on `206 Partial Content` responses.
- R8: `web/runestone/eslint.config.ts` enforces `vue/no-v-html` as an error; HTML and SVG files open only as escaped text source; control bytes render as escaped tokens; and `utils/markdown.ts` + `MarkdownView.vue` parse Markdown into a restricted AST without inline HTML execution or external image requests and route all link clicks through `LinkMenu` for raw URL inspection/copying across file viewers, task/workflow reports, AI summaries, and AI chat.
- R9: `LoginView.vue` renders local username/password sign-in when `local` is present in `VITE_OPENRELIK_AUTH_METHODS`, renders sign-in buttons to `${apiServerUrl}/login/${method}` for configured external providers (such as `google` and `oidc`), hides the local form when `local` is absent, preserves `?redirect=` across local and external login flows, and redirects `/my-folders` and `/shared-with-me` to `/`.
- R10: When `configsApi.system()` reports non-empty `active_llms` and user AI settings (`ai.enabled` plus `ai.summaries` or `ai.chat`) are enabled, `FileView` / `FileSidePanel` renders existing and newly requested file summaries (`POST /api/v1/files/{id}/summaries`, polling `GET /api/v1/files/{id}/summaries/{summary_id}` every 3 seconds while `status_short === 'in_progress'`, with prompt viewer) and provides streaming SSE file chat (`GET /api/v1/files/{id}/chat/history` and `POST /api/v1/files/{id}/chat`, aborting active streams on unmount) for eligible non-database text files.
- R11: `/metrics` renders the ten Celery task Prometheus range-query charts through custom SVG `LineChart.vue` with selectable lookback window, resolution step, and auto-refresh interval.
- R12: `web/runestone/Dockerfile` builds static assets in `node:22-bookworm-slim` and serves port `8711` from `nginx:stable-alpine` substituting `PLACEHOLDER_VITE_OPENRELIK_*` variables at startup; `./devctl stack up` starts both `web-sunstone` (`UI_PORT`, `3000` + slot) and `web-runestone` (`RUNESTONE_PORT`, `3050` + slot) by default with both origins in generated `allowed_origins`; `.github/images.toml` registers `openrelik-web-runestone` (`images.py check` passes); and `.github/workflows/frontend-runestone-tests.yml` runs format, lint, type-check, Vitest coverage, and build checks with a `Frontend Unit Tests [runestone] passed` gate job.
- R13: In the final cutover phase, `openrelik-ui` in `.github/images.toml`, `PLATFORM["ui"]` in `.github/scripts/images.py`, `release_ui` and `components` in `dev/tools/devctl/src/devctl/release.py`, `compose.yml` (`UI_PORT`), and `web/README.md` switch the default UI from `web/sunstone` to `web/runestone`, while keeping `web/sunstone` published as `openrelik-ui-sunstone` and runnable on a secondary dev port.

## Rollout

- No database migrations or `deploy/docker/docker-compose.yml` variable changes are required; `web/runestone/Dockerfile` honours the existing `OPENRELIK_SERVER_URL`, `OPENRELIK_API_VERSION`, and `OPENRELIK_AUTH_METHODS` container environment variables on port `8711`.
- During Phases 1–3, `ghcr.io/openrelik/openrelik-ui` continues publishing `sunstone` while early adopters can opt into `ghcr.io/openrelik/openrelik-web-runestone`, and local developers get both UIs automatically on `./devctl stack up` (`:3000` and `:3050`; existing checkouts regenerate `.dev-local/config/settings.toml` or add `http://localhost:3050` to `allowed_origins`).
- In Phase 4, `ghcr.io/openrelik/openrelik-ui` switches to `runestone` and `ghcr.io/openrelik/openrelik-ui-sunstone` remains published as a fallback image.
