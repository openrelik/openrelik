# Spec: File selection annotations

Implements `idea.md` (#160) and `design.md`. Incorporates the validated backend and Runestone UI from the `prototype/file-selection-annotations` worktree.

## Scope

- Add SQLAlchemy models `FileAnnotation` and `FileAnnotationReply` with check constraints, dual PostgreSQL/SQLite partial indexes, and an Alembic migration.
- Add seven FastAPI endpoints under `/api/v1/files/{file_id}/annotations` for listing, creating, editing, and soft-deleting annotations and threaded replies with file/folder ACL enforcement and IDOR checks.
- Add `annotation_count: int = 0` to `FileResponseCompactList`, populated via a single batched query in `get_files_from_db()`, and surface a comment icon and count beside filenames in Runestone's `FolderTable`.
- Add Runestone selection annotation UI across `TextViewer`, `MarkdownViewer`, `TableViewer`, and `HexViewer`: warm-amber highlight tokens, 3-layer highlight stacking, gutter indicators, scrollbar ticks, floating `SelectionPopover`, `Comments` tab in `FileSidePanel` (responsive overlay below `xl`), minimalist thread cards, `?comment=<id>#...` URL deep-linking, click-outside deselection, arrival pulse animation, and sign-out cache clearing.
- Out of scope: annotation types beyond comments (tags, verdicts), resolve/reopen thread states, storing evidence excerpts in Postgres, Markdown/HTML rendering in comment bodies, `web/sunstone`, global search/reports/exports, and Python client or MCP server support.

## Requirements

- R1: `FileAnnotation` and `FileAnnotationReply` models inherit `BaseModel` in `server/src/datastores/sql/models/file.py`, store `anchor_kind` (`'line' | 'row' | 'offset'`), `BigInteger` `range_start`/`range_end`, paired nullable `Integer` `range_start_col`/`range_end_col`, `UnicodeText` `body`, and nullable timezone-aware `edited_at`, with database check constraints enforcing valid `anchor_kind`, `range_end >= range_start`, lower bounds (`>= 0` for `offset`, `>= 1` for `line`/`row`), paired column nullability, columns restricted to `line`, and positive column numbers. `FileAnnotation.replies` excludes soft-deleted replies and orders active replies by `(created_at, id)`.
- R2: An Alembic migration (`c8d4f2a91e05_add_file_annotation_models.py`, registered in `alembic/env.py`) creates `fileannotation` and `fileannotationreply` with their foreign keys, check constraints, and partial indexes (`ix_fileannotation_file_id_active` and `ix_fileannotationreply_annotation_id_active`, `WHERE NOT is_deleted` for both PostgreSQL and SQLite), and downgrades cleanly.
- R3: Dedicated router `server/src/api/v1/annotations.py` (mounted under `/files` in `server/src/main.py` and `server/src/tests/conftest.py`) exposes `GET/POST /{file_id}/annotations`, `PATCH/DELETE /{file_id}/annotations/{annotation_id}`, `POST /{file_id}/annotations/{annotation_id}/replies`, and `PATCH/DELETE /{file_id}/annotations/{annotation_id}/replies/{reply_id}`.
- R4: Every annotation endpoint enforces `@require_access(allowed_roles=[Role.VIEWER, Role.EDITOR, Role.OWNER])` on `file_id`, verifies `annotation.file_id == file_id` and `reply.annotation_id == annotation_id` (returning `404` on mismatch or soft-deleted records), restricts `PATCH` to the author (`403` otherwise), and restricts `DELETE` to the author or an admin (`403` otherwise). Soft-deleting an annotation cascades `soft_delete()` to its active replies in the same transaction.
- R5: Request schemas validate trimmed non-empty bodies up to 10,000 characters, anchor bounds (`range_end_col > range_start_col` on single-line column spans), and `POST` rejects `offset` ranges where `range_end >= file.filesize` (or `filesize == 0`) with HTTP `400`. `PATCH` updates `edited_at` in UTC; `GET` orders active annotations by `(anchor_kind, range_start, range_end, id)` and omits soft-deleted annotations and replies.
- R6: `FileResponseCompactList` includes `annotation_count: int = 0`, populated in `get_files_from_db()` via a single batched `GROUP BY` query counting active (`NOT is_deleted`) annotations per listed file ID.
- R7: `web/runestone/src/assets/main.css` defines `--color-annotation`, `--color-annotation-tint`, `--color-annotation-overlap`, and `--color-annotation-active` in dark and light themes (passing WCAG contrast assertions in `tokens.test.ts`: >= 7:1 accent on surface, >= 6.5:1 ink on all three highlight layers), `::highlight(annotation*)` rules, and `annotation-pulse` / `annotation-line-flash` keyframes (respecting `prefers-reduced-motion`).
- R8: `useFileAnnotations` caches annotations per file in `useQueryCache` (`file:${fileId}:annotations`), refreshes on `useAutoRefresh`, syncs `annotationCount` onto the matching file in `useItemsStore` after create/delete, and clears all cached annotations via `clearFileAnnotations()` in `stores/auth.ts` on sign-out or 401.
- R9: `SelectionPopover.vue` appears anchored beside the end of a completed pointer selection (text/markdown drag, gutter click/drag across text/table/hex, or multi-byte hex drag; suppressed on single-byte hex clicks, single-row table clicks, and fullscreen table) offering `Comment` and `Copy link`, using `@mousedown.prevent` so focus and selection remain intact for immediate `⌘C`/`Ctrl+C` copying, and dismissing on copy, outside `pointerdown`, `scroll`, `wheel`, `resize`, and `Escape`. Viewer toolbars keep the `MessageSquarePlus` fallback button and `c` shortcut (documented in `HelpDialog.vue`).
- R10: All four viewers highlight saved annotations with three stepped levels (single, overlap, active, with active outranking ephemeral URL `text-mark`): `TextViewer` renders whole-line annotations as row backgrounds (no text underlines) and inline column spans via 3-layer CSS Custom Highlight API (`pointAt()` click hit-testing), plus gutter bars and scrollbar ticks; `MarkdownViewer`/`MarkdownView` tints enclosing source blocks; `TableViewer` tints rows and gutter bars; `HexViewer` tints hex and ASCII cells, gutter bars, and scrollbar ticks.
- R11: Clicking an annotated region in any viewer opens the `Comments` tab, selects its thread (or filters overlapping threads at that point), and updates the URL bar (`?comment=<id>#...`) without scrolling the viewport. Clicking a comment card in the sidebar selects it, updates `?comment=<id>#...`, scrolls the viewer to its range, and triggers a 750ms arrival pulse (`annotation-pulse` or `annotation-line-flash`). Hovering a comment card does not highlight the file.
- R12: Clicking outside any annotated region in a viewer, clicking empty space in the `Comments` sidebar (when no text is selected), or pressing `Escape` deselects the active comment and clears `?comment=` and the URL hash. Opening a file URL with `?comment=<id>` auto-opens the `Comments` tab, selects that comment once loaded, lands on its range, and plays the arrival pulse.
- R13: `FileSidePanel` adds a `Comments` tab (with tabular count) that opens by default when a file has annotations (unless the user pinned another tab) and renders as a fixed overlay `<SlidePane>` below `xl` (removing `max-xl:hidden`).
- R14: `FileAnnotationsPanel` renders threads as stacked cards (transparent with `border-border` when unselected; `bg-warning-tint/35` with `border-warning-icon/40` when selected; edge-to-edge internal dividers), with `sm` avatars, compact UTC timestamps (full UTC seconds on tooltip), right-aligned clickable coordinate chips, 3-line body clamping with neutral `Show more`/`Show less`, a borderless resting `Reply…` prompt that expands to a `.field` box on focus, and a `⋮` menu shown only on the active thread (`Copy link` for all users; `Edit` for author; `Delete` with confirmation for author or admin). All bodies escape C0/C1 control and Unicode bidi characters and render strictly as plain text with zero `v-html`.
- R15: `FolderTable` renders a speech-bubble icon (`fill-annotation-active text-warning-icon`) and tabular count beside the filename whenever `row.kind === 'file' && row.annotationCount > 0`.
- R16: Runestone changes add zero new runtime dependencies, import icons only from `@/components/icons`, use no `../` imports, pass `npm run format:check`, `npm run lint:check`, `npm run type-check`, `vitest`, and `npm run build`, and server changes pass `pytest` and `black --check`.
